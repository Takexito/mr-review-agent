# Участие в разработке

Исправления, улучшения и отчёты об ошибках приветствуются. Если доработали бота у себя — пришлите
PR: поддерживать форк дороже, чем одну ветку здесь.

## Перед PR

- Для заметного изменения поведения сначала откройте issue: обсудим подход до кода.
- Уязвимости — не в issue, а через приватный отчёт (см. [SECURITY.md](SECURITY.md)).
- Если нужное поведение можно получить через `service.yaml` или `.review.yml`, лучше расширить
  конфигурацию, чем добавлять особый случай в код.

## Разработка

Нужны Node 20+ и Redis для локального запуска (тестам Redis не нужен).

```bash
npm ci
npm run typecheck
npm test
npm run build
```

Подробности запуска — в README → «Локальная разработка», сухой прогон без публикации заметок — в
README → «Сухой прогон».

- Новое поведение — с тестом, через публичный интерфейс модуля.
- Сообщения коммитов — [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/)
  (`feat:`, `fix:`, `docs:`, …).
- Заметное пользователю изменение — строка в `CHANGELOG.md` в разделе `[Unreleased]`.
- Никаких реальных токенов, адресов и названий частных проектов в коде, тестах и фикстурах.

## Лицензия вклада и подпись (DCO)

Проект распространяется под [Apache License 2.0](LICENSE). Присылая PR, вы соглашаетесь, что ваш
вклад лицензируется на тех же условиях (раздел 5 лицензии).

Каждый коммит подписывается по [Developer Certificate of Origin](https://developercertificate.org/):
подпись подтверждает, что вы вправе отдать этот код под лицензией проекта. CI проверяет, что у
каждого коммита PR есть `Signed-off-by` с именем и почтой его автора.

```bash
git commit -s -m "fix: ..."
```

Флаг `-s` добавляет строку `Signed-off-by: Имя <email>` с данными из `git config`. Забыли подписать
коммиты ветки — `git rebase --signoff main` и `git push --force-with-lease`.
