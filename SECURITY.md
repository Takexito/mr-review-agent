# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Используйте приватный отчёт GitHub: вкладка **Security →
Report a vulnerability** в этом репозитории. Опишите сценарий, затронутую версию (коммит) и, если
есть, способ воспроизведения. Поддерживается только последняя версия ветки `main`.

## Модель угроз

Бот запускает CLI-агента (`codex`, `claude`) на коде MR и публикует его ответ в GitLab. Всё, что
попадает в промпт — вопрос после упоминания бота, описание, код и треды MR, текст задач из
коннекторов, — может управлять агентом (prompt injection). Поэтому граница доверия проходит по
тем, кто может комментировать MR обслуживаемых проектов.

Бота запускают только участники проекта с ролью не ниже `triggerRole` профиля (по умолчанию
Developer). Но код и описание MR пишет его автор, а это может быть кто угодно, если проект принимает
MR из форков. **Разворачивайте бота там, где и комментаторы, и авторы MR — доверенные участники.**

Что уже сделано, описано в README → «Безопасность»: проверка роли автора заметки, окружение агента
по allowlist, песочница codex `read-only`, сеть агенту по умолчанию закрыта, секреты и quick actions
вычищаются из исходящих заметок, internal-заметки не попадают в промпт, `.review.yml` читается
только из защищённой ветки, timing-safe проверка вебхука.

## Известные ограничения

- **Агент работает под тем же пользователем ОС, что и бот.** Он может прочитать файлы, доступные
  этому пользователю: сессию подписки (`$CODEX_HOME/auth.json`), токены коннекторов (`mcp.json`
  джобы), кэш клонов других проектов, каталоги параллельных джоб. Известные значения секретов
  вычищаются из заметок, но закодированный или разбитый на части секрет этот фильтр пропустит.
  Изоляция агента (отдельный UID или контейнер на джобу) не сделана.
- **Нет лимита джоб на MR и автора.** Участник с нужной ролью может поставить в очередь много
  ревью и выбрать лимиты подписки.
- **Токены коннекторов видят всё, что разрешает их scope.** Задачу, доступную токену, бот может
  процитировать в MR, даже если её не видит автор комментария. Выдавайте токены только на чтение
  и только к нужным командам и проектам.
- **Одни токены на все профили одного экземпляра.** Для проектов с разной аудиторией поднимайте
  отдельные экземпляры бота со своими `.env` и `service.yaml`.
- **`/healthz` без аутентификации.** Он показывает состояние токенов и сиата; наружу публикуйте
  только `/webhook` (см. DEPLOY.md).
