# Смежные репозитории — git-чекауты на диске, а не коннекторы

Документация, бэкенд для клиентского MR и прочий нужный агенту код подключаются как смежные репозитории: профиль или `.review.yml` перечисляет `{project, ref, hint}`, бот выкладывает каждый только для чтения рядом с worktree MR. Grep и чтение по полному чекауту работают у обоих движков и точнее поиска через MCP. `docs-repo` становится одним из смежных репозиториев.

## Consequences

- Кэш смежного репозитория — полный bare-клон со всеми ветками, как у основного: агент читает любую ветку (`git show <ветка>:<файл>`) без сети. Частичный клон (`--filter=blob:none`) не подходит — он докачивает содержимое по сети в момент чтения, а сети у агента нет.
- Первый клон большого репозитория занимает минуты; дальше — инкрементальный fetch.
- `ref` — фиксированная ветка (по умолчанию ветка репозитория по умолчанию) или `same-branch`: ветка с тем же именем, что у MR, если она есть, иначе ветка по умолчанию. Взятая ветка печатается в шапке заметки.
