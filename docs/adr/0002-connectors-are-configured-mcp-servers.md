# Коннекторы — готовые MCP-серверы, объявленные в конфиге

Внешняя система (Linear, Jira, Notion, Figma, Sentry, GitLab…) подключается записью в конфиге: stdio-команда или URL готового MCP-сервера, секреты по ссылке, необязательный список разрешённых инструментов, подсказка для промпта, необязательное правило предзагрузки. Бот переводит запись в настройки движка (`mcp.json` + `--allowedTools` у claude, `-c mcp_servers.*` + `enabled_tools` у codex) и не содержит кода под конкретную систему. Защита от записи — токен только на чтение на стороне самой системы; список инструментов лишь убирает из выдачи агенту лишнее.

## Considered Options

- **Свои обёртки на каждую систему** (как было с Linear и GitLab в `ctxmcp` + shell-CLI). Отклонено: код на каждый источник, а CLI-дубль существовал только потому, что старый codex не вызывал MCP под песочницей.
- **Свой MCP-шлюз** (или Docker MCP Gateway / ContextForge) перед всеми серверами. Отклонено на текущем масштабе: оба движка сами принимают несколько серверов с фильтром инструментов. Вернуться, когда понадобятся централизованный аудит и секреты по многим проектам.
- **Защита белым списком инструментов на нашей стороне.** Отклонено как основная мера: обходится, если сервер называет пишущий инструмент безобидно; токен только на чтение держит запрет на стороне системы.

## Consequences

- Свой MCP-сервер `ctxmcp`, `cli/linear.ts` и `cli/gitlab.ts` удаляются. Описание и все треды текущего MR бот кладёт файлами в каталог джобы.
- GitLab — такой же коннектор (готовый сервер с токеном `read_api`). Скачивание вложений готовые серверы не обещают, поэтому картинки из описания MR и прямых целей скачивает бот; картинки по более глубоким ссылкам агенту недоступны.
- Удалённые серверы с интерактивным OAuth (hosted Notion, Linear, Atlassian, Figma) не поддерживаются — только серверы, принимающие токен.
- Токен только на чтение видит всё, что видит его владелец: на каждую организацию — сервисный аккаунт с доступом лишь к нужным командам и пространствам.
- Сеть у самого агента — отдельная опция профиля (`agentNetwork`), по умолчанию выключена: коннекторам она не нужна, MCP-серверы ходят в сеть вне песочницы агента. Включение — ослабление: всё, что агент прочитал, он может отправить наружу (prompt injection в тексте задачи). Для codex это `workspace-write` + `network_access` — запись в worktree и TMPDIR, поэтому кэш репозиториев обязан лежать вне TMPDIR; для claude — разрешение сетевых инструментов в `--allowedTools`.
- CLI-инструменты (`glab` и т.п.) профиль может включить явно (`cliTools`), и только вместе с `agentNetwork`. Сверх сети это кладёт токен в окружение агента — его тоже можно увести.
- **Условие решения** — проверено сухим прогоном на codex 0.166.0 (2026-11-05): под `--sandbox read-only` shell агента сети не имеет (`curl` → exit 6), а MCP-сервер ходит в сеть; `enabled_tools` оставляет агенту только перечисленные инструменты; `tools/call` проходит **только** с `default_tools_approval_mode="approve"` на сервере (или `approval_mode="approve"` на инструменте) — без этого `codex exec` отклоняет вызов («requires approval, but approval policy is never»), а `"auto"` и `approval_policy="on-request"` не помогают. При обновлении codex проверку повторять.
