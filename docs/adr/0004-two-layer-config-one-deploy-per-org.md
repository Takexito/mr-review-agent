# Конфигурация в два слоя, один деплой на организацию

Один экземпляр сервиса обслуживает одну организацию: один хост GitLab, свои бот-аккаунты, много проектов. Настройки лежат в двух слоях: `service.yaml` администратора (движки, бот-аккаунты, коннекторы, профили проектов по glob, секреты ссылками `secret:NAME` на env) и `.review.yml` в репозитории (стандарты, исключения, сужение списка коннекторов, смежные репозитории). Конфигурация только через env, как сейчас, убирается без обратной совместимости.

## Considered Options

- **Мультиарендность в одном процессе.** Отклонено: изоляция секретов и квот подписки между организациями — отдельный большой проект; новая организация получает свой экземпляр.
- **Общий интерфейс площадки MR с заделом под GitHub.** Отклонено: интерфейс с одной реализацией почти наверняка окажется неправильным; код GitLab держится в своём модуле.

## Consequences

- `.review.yml` читается из **target-ветки**, а не из head MR: иначе автор MR в том же MR выключит себе стандарты или подключит лишнее.
- `.review.yml` может только сужать список коннекторов профиля и добавлять смежные репозитории, прошедшие allowlist сервиса; секретов в нём не бывает.
