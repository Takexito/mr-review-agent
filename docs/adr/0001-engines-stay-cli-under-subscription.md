# Движки остаются CLI-процессами под подпиской

Ревью исполняют `codex exec` и `claude -p`, запущенные как процессы под подпиской (ChatGPT, Claude Pro/Max), а не SDK или API провайдеров: через SDK подписка не работает, а платить за API по токенам на агентном обходе больших MR мы не готовы. Каждый движок пишет в MR от своего бот-аккаунта, и автор MR видит, какой движок ответил; профиль проекта задаёт, какие движки в нём включены.

## Considered Options

- **Claude Agent SDK / codex SDK.** Давали бы журнал вызовов инструментов и структурированный вывод из коробки, но не работают на подписке.
- **Построиться на открытом ревьюере (PR-Agent, Kodus).** Оба вызывают LLM по API и работают с диффом в промпте, а не агентом по репозиторию; переделка под CLI-движки равна написанию заново. Берём у них идеи: слои конфигурации (PR-Agent), плагины как MCP (Kodus).
- **Один бот-аккаунт с выбором движка аргументом команды.** Отклонено: в MR не видно, какой движок ответил.

## Consequences

Всё, что SDK дал бы бесплатно (журнал вызовов, структурированный результат), добываем из потока событий CLI (`codex exec --json`, `claude --output-format stream-json`) или из маркеров в тексте ответа.
