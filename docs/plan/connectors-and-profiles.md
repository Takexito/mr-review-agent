# План: коннекторы, профили проектов, смежные репозитории

Реализация решений из [ADR 0001–0005](../adr/). Шаги идут по порядку: каждый следующий опирается на предыдущий.

- [x] **0. Проверка условия ADR 0002.** Сухой прогон на codex 0.166.0 (2026-11-05): все три условия выполняются при `default_tools_approval_mode="approve"` на сервере. В `--json` у codex есть события `mcp_tool_call` (сервер, инструмент, статус) — основа для шага 6.
- [x] **1. Конфигурация в два слоя** ([0004](../adr/0004-two-layer-config-one-deploy-per-org.md)). `service.yaml`: движки, бот-аккаунты, коннекторы, профили проектов по glob, `secret:NAME`. Перенос текущего деплоя с env.
  - Файл по пути `SERVICE_CONFIG` (по умолчанию `/config/service.yaml`); разбор — чистая функция `parseServiceConfig(yaml, env)`, ошибки собираются все сразу, значения секретов в них не попадают.
  - Поля-секреты (токены, `webhookSecret`) принимают только `secret:NAME`: открытый текст в файле — ошибка запуска. Ссылка на пустую или отсутствующую переменную — ошибка запуска.
  - `engines.codex` обязателен, `engines.claude` — по наличию секции; бот-аккаунт — `bot: {username, token}` внутри движка.
  - `connectors` и опции профиля `agentNetwork`/`cliTools` разбираются и проверяются (ссылки профиля на коннекторы, `cliTools` только с `agentNetwork`), но подключаются в шаге 2.
  - Профили: `projects` — glob по `path_with_namespace` (`*` — внутри сегмента, `**` — любые сегменты), первый совпавший побеждает; нет совпадения — проект не обслуживается (замена `PROJECT_ALLOWLIST`). `engines` профиля сужает, какие боты отвечают в проекте.
  - Временно в env, до своих шагов: `LINEAR_API_*`, `GITLAB_READ_TOKEN`, `CODEX_MCP_ENABLED`, `CODEX_ONDEMAND_LINEAR` (шаг 2), `DOCS_REPO_*` (шаг 3).
  - Деплой: `service.example.yaml`, монтирование в `docker-compose.yml`, `.env` — только секреты и временные переменные.
- [x] **2. Коннекторы из конфига** ([0002](../adr/0002-connectors-are-configured-mcp-servers.md)). Перевод записей в настройки claude и codex; подсказки в промпт из конфига. Linear и GitLab — на готовых MCP-серверах с токенами только на чтение (выбрать серверы). Описание и треды MR — файлами в каталог джобы. Удалить `ctxmcp`, `cli/linear.ts`, `cli/gitlab.ts`, раскладку Linear на диск, `CODEX_ONDEMAND_LINEAR`, `CODEX_MCP_ENABLED`. Вернуть codex в `read-only` с `default_tools_approval_mode="approve"` на каждом сервере. Опции профиля `agentNetwork` (по умолчанию выкл.) и `cliTools` (требует `agentNetwork`).
  - Перевод — чистые функции `src/connectors/engineConfig.ts`. Имя коннектора — `[A-Za-z0-9-]+`: codex делит ключ `-c` по точкам.
  - Серверы для примера: `@zereight/mcp-gitlab` (`GITLAB_PERMISSION_MODE=readonly`), `@tacticlaunch/mcp-linear`. Имена инструментов в `tools` сверить по `tools/list` при подключении.
  - `cliTools` пока только разрешает команду (`Bash(<tool> *)` у claude); токен для CLI в окружение агента не передаётся.
  - Остаётся в env до шага 4: `LINEAR_API_*` — ими бот скачивает задачу-постановку (`spec/sources.ts`). Задачи GitLab для оси постановки бот качает токеном бота codex; `GITLAB_READ_TOKEN` удалён.
- [x] **3. Смежные репозитории** ([0005](../adr/0005-related-repos-are-disk-checkouts.md)). `related` в профиле, `same-branch`, `docs-repo` — через этот механизм.
  - `related: [{project, ref?, hint?}]` в профиле; выкладка — `src/related/checkout.ts`, каталог `<jobdir>/related/<group>+<project>`. `DOCS_REPO_*` удалены: docs-repo — запись в `related`.
  - Взятая ветка пока печатается в лог (`related repositories ready`) и в промпт; в шапку заметки — в шаге 6, вместе с «Открыто агентом».
  - Чекаут доступен агенту на запись, когда codex в `workspace-write` (общий `review`, `agentNetwork`): каталог джобы лежит в TMPDIR. Bare-кэш при этом защищён — он вне TMPDIR.
- [x] **4. Новая предзагрузка** ([0003](../adr/0003-prefetch-only-direct-targets.md)). Правила прямых целей и `issueKeys`; бот — MCP-клиент коннектора; привязанные документы; режимы inline/файлы с проверкой, что каждая цель в чек-листе; картинки из описания MR и целей. Удалить старую `spec/sources.ts` и поиск ключей по всему описанию.
  - Профиль: `issueKeys: { PRJ: linear, "#": gitlab }` — префикс → коннектор профиля с правилом `prefetch: {tool, arguments}`; в шаблоне `{key}`, `{number}`, `{project}`. `#` — задачи GitLab: `#34`, `group/project#34`, URL задачи своего хоста, ветка `34-…`. Правила — `src/spec/targets.ts`, скачивание — `src/spec/prefetch.ts` (одна MCP-сессия на коннектор за джобу).
  - Аргумент команды заменяет автопоиск; токен, не подошедший ни под один префикс, — в «Неполные источники». Ось агенту больше не поручает делить источники на постановку и контекст: `ignoredSources` удалён, у пункта чек-листа есть `target` — метка цели. Ссылки строки привязки — только список сразу за ключевым словом, как у GitLab. Задачи GitLab и вложения — только проекта MR и смежных репозиториев профиля: иначе бот своим токеном читал бы за автора MR то, к чему у того нет доступа. Не больше 10 целей за джобу; текст ошибки инструмента — через `redactSecrets` и не длиннее 500 символов.
  - Порог `review.targetsInlineMaxChars` (60 000). В режиме файлов цели без пунктов дочитываются одним повторным прогоном; оставшиеся — предупреждение в заметке.
  - Нет `issueKeys`, нет цели или ни одна не скачалась — `spec` пишет заметку без запуска агента, `review` — строку в разделе постановки.
  - Картинки — только вложения своего GitLab (`/uploads/…`) из описания MR и текста целей, плюс image-части ответа инструмента; в `<jobdir>/images`. `src/linear/`, `gitlab/fetchUrl.ts`, `LINEAR_API_*` удалены.
- [x] **5. `.review.yml` в репозитории** ([0004](../adr/0004-two-layer-config-one-deploy-per-org.md)). Чтение из target-ветки, слияние с профилем (только сужение коннекторов, смежные репозитории из allowlist).
  - Поля: `connectors` (подмножество профиля; `issueKeys` выбывших коннекторов отпадают), `related` (через `relatedAllowlist` профиля — glob, пусто = нельзя; уже выложенный профилем — ошибка), `exclude` (git glob pathspec от корня — файлы выпадают из диффа и чек-листа), `standards` (ось стандартов читает их первыми).
  - Слияние — чистая `applyRepoConfig` (`src/config/repoConfig.ts`); файл — `git cat-file` из `refs/heads/<ветка>` bare-кэша, до 64 КБ. Ветка — target MR, если она защищённая или по умолчанию (`Branches.show`), иначе ветка по умолчанию. Пути `exclude`/`standards` — только `[A-Za-z0-9_.*?[\]/-]`: они уходят в команду, которую агент копирует в shell.
  - Любая ошибка (в том числе файл больше 64 КБ) — файл игнорируется целиком, бот пишет заметку со списком ошибок (кроме ответов на вопросы); значения из файла в ней — только в код-спане, без markdown и упоминаний. `ref` смежного репозитория — только имя ветки, общая схема с `service.yaml`.
  - Агент в agentic-режиме получает команду `git diff` с теми же исключениями; объявленные стандарты читает из target-ветки (`git show <target>:<путь>`), а не из head MR. Находки по исключённым путям при публикации не отфильтровываются.
- [ ] **6. Журнал вызовов.** Разбор событий `codex exec --json` / `claude --output-format stream-json`; «Открыто агентом: …» и ветки смежных репозиториев в шапке заметки.
- [ ] **7. Хвосты.**
  - **Изоляция джоб.** Агенты всех джоб работают под одним пользователем: агент одной джобы читает `mcp.json` и окружение MCP-процессов другой (токены коннекторов чужого профиля). Нужен отдельный UID или контейнер на джобу.
  - **Токены для `cliTools`.** Профиль только разрешает команду (`Bash(<tool> *)` у claude), токен в окружение агента не передаётся — `glab` без авторизации не работает. Нужно поле токена у CLI-инструмента (`secret:NAME`), с той же оговоркой ADR 0002: токен в окружении агента можно увести.
  - **Проверка на живом деплое.** Вписать коннекторы GitLab и Linear в `service.yaml` с токенами только на чтение; сверить имена в `tools` и `prefetch` (имя инструмента, имена и типы аргументов — шаблон даёт только строки) с `tools/list` серверов (`@zereight/mcp-gitlab`, `@tacticlaunch/mcp-linear`); сухой прогон codex и claude с коннекторами.
  - **Общий лимит предзагрузки.** Цели качаются по очереди, каждый вызов — до 120 с; зависший сервер коннектора задерживает джобу на N×120 с. И `spec` без цели узнаёт об этом уже после выкладки смежных репозиториев.
  - **Картинки с чужих хостов.** Вложения Linear (`uploads.linear.app`) требуют токен Linear: бот их не скачивает, агент видит только пометку в «Неполные источники». Нужен способ дать коннектору заголовки для своих вложений.
